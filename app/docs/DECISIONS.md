# Decision log (v1)

| Date | Decision | Why | Alternatives rejected |
|---|---|---|---|
| 2026-10-05 | v1 lives in `/app` with its own `tsconfig.json`, `vite.config.ts`, and `vitest.config.ts`; the repo's `package.json` gains `app:*` scripts and a `prepare` script for the commit hook, and nothing else at the root changes. | The brief says build in a new folder and do not change existing code. Separate configs keep v2's typecheck, tests, and build exactly as they were. | Adding `/app` to the root `tsconfig` include (would widen v2's typecheck and tests); a second `package.json` in `/app` (two installs, two lockfiles). |
| 2026-10-05 | The repo-root `CLAUDE.md` keeps its existing v2 rules and gains a section "Working in /app (v1)" with the rules the brief lists. | The existing file governs the v2 code that stays in the repo; replacing it would silently drop rules the v2 branches rely on. | Overwriting `CLAUDE.md`; a second `CLAUDE.md` inside `/app` (the brief says repo root). |
| 2026-10-05 | v1 reuses v2 engine functions only from the short list in `docs/INVENTORY.md` section 6, by direct import, and never the timeline, optimizer, or UI. | Those functions are pure, tested, and in two cases tied out; the rest is self-serve product. | Copying code into `/app` (two copies to keep in step); reusing the whole engine (a 1,600-line timeline is the wrong shape for a coach's one-pager). |
| 2026-10-05 | Statuses are `empty`, `unknown`, `rough`, `entered`, `verified`, `none`, `notApplicable`. `none` counts as complete and as 0; `notApplicable` makes dependent metrics report `notApplicable` instead of waiting. | The brief's list, made machine-checkable. | Folding `none` into `entered: 0` (loses the distinction between "zero" and "typed a zero by habit"). |
| 2026-10-05 | A `Composite` input holds a `total` and `lines`; when any line is complete the lines win. Missing lines follow the metric's missing policy. | The brief: detail automatically overrides the total. | Summing lines into the total on write (a stored derived value). |
| 2026-10-05 | The metrics registry recomputes only the metrics downstream of a changed input, found by walking the declared dependency edges; results are cached per metric and invalidated by path. | The brief: a dependency graph. | Recomputing everything on every change (simple, but hides a missing declaration). |
| 2026-10-05 | Missing policies are `wait`, `default`, and `zero`; a metric declares one per input. `zero` is allowed only where the metric's definition says a missing value is safely zero, and the test for the metric must show the case. | The brief. | A global policy per status. |
| 2026-10-05 | The assumptions drawer carries three cases, `realistic`, `likely`, `unrealistic`, with the same field set; `likely` is active by default; values start from v2's assumption sets (`data/assumption-sets.json`, worst, likely, best) with a note that they are proposed. | The brief names the three cases; v2 already has three sourced-as-proposed bands. | New placeholder values with no lineage. |
| 2026-10-05 | The file carries `schemaVersion` (starting at 1), and `migrate()` upgrades one step at a time and refuses a newer version than it knows. | The brief. | A free-form version string. |
| 2026-10-05 | Snapshots are stored inside the client's working copy (the browser's storage), capped at 20, taken before every import and at the start of each session; an exported file carries the client's snapshots so a folder copy is self-contained. Undo restores the snapshot taken just before the last import. | The brief; a snapshot is useless if it lives only where the overwritten data lived. | Snapshots as separate files (the coach would have to manage them). |
| 2026-10-05 | Client files are refused by a pre-commit hook in `.githooks/`, installed by `npm run prepare` (sets `core.hooksPath`), plus `.gitignore` rules. The check also runs as a test. | Git hooks are not versioned; `core.hooksPath` is the lightest way to version one. | A husky dependency. |
| 2026-10-05 | The coach console in v1 uses the browser's file picker and download for export and import ("a folder you choose"), with the File System Access API used when the browser offers it. | Works in every browser; no server. | A Node or Electron shell (later, if the pilot needs it). |
| 2026-10-05 | The client label is a nickname the coach chooses; the template says never a legal name. | Client data must never reach the repo, and a nickname limits what a stray file reveals. | Full names with a warning. |
| 2026-10-05 | The DRAFTT scorecard is a Sun view (reads published outputs, owns nothing), as the brief's contracts draft says; its category mapping copies v2's `drafttLens`. | A scorecard that owned facts would make three planets write the same numbers. | DRAFTT as its own planet. |
| 2026-10-05 | The one-time card for this session is card 1 only; cards 2 to 12 stay "Not started". | The brief scopes this session to the foundation. | Starting card 2 while the foundation is unreviewed. |
